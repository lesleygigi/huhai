# Task 5：最小游戏播放器 ✅

## 任务目标

实现《胡亥模拟器》的最小游戏播放器，让浏览器页面不再显示 Vite 默认内容，而是直接进入可玩的序章原型。

Task 5 完成后，玩家应能在浏览器中：

- 看到《胡亥模拟器》的序章界面。
- 读取当前剧情文本。
- 看到当前可选项。
- 点击 A/B/C 选项推进剧情。
- 点击“重新开始”回到序章开头。

## 任务范围

需要涉及的文件：

```text
src/App.tsx
src/components/GameView.tsx
src/components/TextBox.tsx
src/components/ChoiceList.tsx
src/components/BackgroundLayer.tsx
src/components/PortraitLayer.tsx
src/styles/game.css
src/index.css
src/App.css
```

依赖前置任务：

- Task 3：`story/main.ink` 和 `story/prologue.ink` 已存在。
- Task 4：`public/story/main.json` 可生成，`src/engine/ink.ts` 可加载剧情。

不包含：

- 完整调试面板能力。
- 存档读档。
- 结局判定。
- 正式背景和立绘素材。
- 完整音频控制。

这些内容属于 Task 6、Task 7、Task 8、Task 10。

## Step 5.1：实现 `GameView`

### 目标

用 `GameView` 承载完整游戏界面，替换 Vite 默认页面。

### 实施内容

`src/App.tsx` 应只负责挂载游戏主界面：

```tsx
import { GameView } from "./components/GameView";

function App() {
  return <GameView />;
}

export default App;
```

`GameView` 负责：

- 调用 `loadStory()` 加载 Ink 剧情。
- 保存当前 `StoryRuntime`。
- 保存当前 `StorySnapshot`。
- 显示加载中状态。
- 显示加载失败状态。
- 显示游戏主界面。
- 连接文本框、选项列表、背景层、立绘层和基础调试区域。

建议界面结构：

```tsx
<main className="game-view">
  <BackgroundLayer />
  <PortraitLayer />
  <section className="game-shell">
    <header />
    <TextBox />
    <ChoiceList />
  </section>
  <DebugPanel />
</main>
```

### 验收标准

- 浏览器页面不再显示 Vite 默认页。
- 页面直接显示《胡亥模拟器》相关标题或序章内容。
- `GameView` 能调用 `loadStory()`。
- 加载成功后能显示序章文本。
- 加载失败时有错误提示，而不是白屏。
- `npm --cache ./.npm-cache run build` 构建通过。

## Step 5.2：实现 `TextBox`

### 目标

显示当前剧情文本，并保证多行文本可读。

### 实施内容

`TextBox` 接收当前文本行：

```ts
type TextBoxProps = {
  lines: string[];
};
```

基础行为：

- 将 `lines` 渲染为段落。
- 保留多行叙述和角色台词。
- 容器支持滚动，避免长文本溢出。
- 空文本时显示合理占位或保持区域稳定。

样式要求：

- 文本区域清晰可读。
- 行高适合长文本阅读。
- 文本不会超出容器边界。
- 移动端不会横向溢出。

### 关于“点击继续”

当前 Task 4 的运行时会一次性推进到选项节点，因此 Task 5 可先显示当前批次文本，不强制逐句点击继续。

如果要实现“点击继续”，可以采用临时前端分页：

- `lines` 全量保留。
- 前端维护 `visibleLineCount`。
- 点击文本框逐行增加显示。
- 到最后一行后显示选项。

这一增强可在 Task 5 内完成，也可后续作为体验优化。

### 验收标准

- 多行文本排版正常。
- 长文本不会溢出容器。
- 可以看到序章开场文本。
- 可以看到赵高相关台词。
- 文本区域在桌面端和移动端都可阅读。

## Step 5.3：实现 `ChoiceList`

### 目标

显示当前可选项，并在点击后推进 Ink 剧情。

### 实施内容

`ChoiceList` 接收选项和回调：

```ts
type ChoiceListProps = {
  choices: string[];
  onChoose: (index: number) => void;
};
```

基础行为：

- 当前有选项时显示按钮列表。
- 点击按钮时调用 `onChoose(index)`。
- 选择后调用 `runtime.choose(index)`。
- 更新当前 `StorySnapshot`。
- 无选项时不显示按钮，或显示“本段结束”提示。

### 验收标准

- A/B/C 三个序章选项都能显示：
  - 同意矫诏。
  - 拒绝并告发。
  - 表面答应，暗中布局。
- 三个选项都可点击。
- 点击后文本发生变化。
- 点击后剧情进入对应临时结算段落。
- 点击 A 后能看到【矫诏同谋】相关结算。
- 点击 B 后能看到【曾试图告发】相关结算。
- 点击 C 后能看到【隐忍待发】相关结算。

## Step 5.4：实现重新开始

### 目标

方便反复测试序章三条分支。

### 实施内容

在 `GameView` 中实现 `restart()`：

```ts
function restart() {
  const nextSnapshot = runtime.restart();
  setHistory([]);
  setSnapshot(nextSnapshot);
}
```

基础行为：

- 重置 Ink Story。
- 清空当前选择历史。
- 清空临时 UI 状态。
- 回到序章开头。

如果已经实现了基础调试区域，应同时确认：

- `fear` 回到初始值。
- `zhao_gao` 回到初始值。
- `strategy` 回到初始值。
- `flags` 回到初始状态。

### 验收标准

- 页面上存在“重新开始”按钮。
- 点击任意分支后，再点击“重新开始”，文本回到序章开头。
- 重新开始后 A/B/C 三个选项重新可见。
- 重新开始后数值和标记回到初始状态。
- 重新开始后选择历史清空。

## Step 5.5：基础视觉和布局

### 目标

让最小播放器具有可读、稳定的游戏界面，而不是裸文本。

### 实施内容

基础布局：

- 全屏游戏视图。
- 背景层。
- 立绘层或临时角色占位。
- 文本框。
- 选项区。
- 顶部标题区。

样式要求：

- 文本框不遮挡选项。
- 选项按钮大小稳定。
- 按钮 hover 状态不导致布局跳动。
- 移动端文本不横向溢出。
- 背景层和立绘层不阻挡点击。

### 验收标准

- 桌面端可正常阅读和选择。
- 移动端宽度下不出现横向滚动。
- 选项按钮不会因为 hover 改变尺寸。
- 背景层、立绘层、文本框和选项区层级正确。

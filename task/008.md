# Task 8：演出标签解析 ✅

## 任务目标

实现 Ink 演出标签到前端表现层的完整链路，让剧情脚本中的 `# bg`、`# show`、`# hide`、`# music`、`# sfx` 等标签能够驱动背景、立绘和音频。

Task 8 完成后，`story/prologue.ink` 中的标签应能影响前端画面和声音：

- `# bg: sha_qiu_night` 切换背景。
- `# show: zhao_gao serious right` 显示赵高立绘占位。
- `# hide: zhao_gao` 隐藏赵高。
- `# music: night_palace` 播放或准备播放 BGM。
- `# sfx: door_open` 播放或准备播放音效。

## 任务范围

需要涉及的文件：

```text
src/engine/tags.ts
src/components/GameView.tsx
src/components/BackgroundLayer.tsx
src/components/PortraitLayer.tsx
src/styles/game.css
data/assets.json
public/images/backgrounds/
public/images/portraits/
public/audio/music/
public/audio/sfx/
```

可选新增：

```text
src/engine/audio.ts
src/engine/presentation.ts
```

依赖前置任务：

- Task 3：Ink 剧情中已有演出标签。
- Task 4：`StorySnapshot.tags` 能读取 Ink 当前标签。
- Task 5：页面已有背景层和立绘层。

不包含：

- 正式美术资源制作。
- 正式音乐和音效制作。
- 复杂时间轴演出。
- 对话逐字播放。

## Step 8.1：实现 `tags.ts`

### 目标

解析 Ink 标签字符串，转换为前端可消费的结构化指令。

### 输入示例

```text
bg: sha_qiu_night
show: zhao_gao serious right
hide: zhao_gao
music: night_palace
sfx: door_open
fade: black
shake: light
```

### 输出示例

```ts
{
  type: "show",
  character: "zhao_gao",
  expression: "serious",
  position: "right"
}
```

### 实施内容

`src/engine/tags.ts` 至少支持：

- `bg`
- `show`
- `hide`
- `music`
- `sfx`
- `fade`
- `shake`
- `unknown`

建议类型：

```ts
type StoryTag =
  | { type: "bg"; id: string }
  | { type: "show"; character: string; expression: string; position: "left" | "center" | "right" }
  | { type: "hide"; character: string }
  | { type: "music"; id: string }
  | { type: "sfx"; id: string }
  | { type: "fade"; color: string }
  | { type: "shake"; intensity: string }
  | { type: "unknown"; raw: string };
```

同时建议提供批量解析函数：

```ts
export function parseStoryTags(tags: string[]): StoryTag[];
```

### 验收标准

- `parseStoryTag("bg: sha_qiu_night")` 返回背景指令。
- `parseStoryTag("show: zhao_gao serious right")` 返回角色、表情和位置。
- `parseStoryTag("hide: zhao_gao")` 返回隐藏角色指令。
- `parseStoryTag("music: night_palace")` 返回音乐指令。
- `parseStoryTag("sfx: door_open")` 返回音效指令。
- 未知标签返回 `unknown`，不会导致游戏崩溃。
- 缺少参数的标签不会导致页面白屏。

## Step 8.2：建立演出状态

### 目标

将一批标签应用为当前画面状态，避免每个组件各自解析标签。

### 实施内容

建议在 `GameView` 或 `src/engine/presentation.ts` 中维护：

```ts
type PresentationState = {
  background?: string;
  portraits: Record<"left" | "center" | "right", PortraitState | null>;
  music?: string;
  sfxQueue: string[];
  fade?: string;
  shake?: string;
};
```

`PortraitState`：

```ts
type PortraitState = {
  character: string;
  expression: string;
};
```

标签应用规则：

- `bg` 设置当前背景 ID。
- `show` 设置指定位置的角色。
- `hide` 移除指定角色，不论其在哪个位置。
- `music` 设置当前 BGM ID。
- `sfx` 加入一次性音效队列。
- `fade` 设置淡入淡出状态。
- `shake` 设置震屏状态。

### 验收标准

- 初始标签能产生背景 ID：`sha_qiu_night`。
- 初始标签能产生胡亥左侧立绘状态。
- 初始标签能产生赵高右侧立绘状态。
- 选择 A 后能把赵高状态更新为 `smile`。
- 选择 B 后 `hide: zhao_gao` 不会造成崩溃，并可继续应用后续 `show`。

## Step 8.3：实现背景层

### 目标

根据 `bg` 标签切换背景。

### 实施内容

`BackgroundLayer` 接收背景 ID 或背景路径。

数据来源：

```text
data/assets.json
```

示例：

```json
{
  "backgrounds": {
    "sha_qiu_night": "/images/backgrounds/sha_qiu_night.webp"
  }
}
```

如果素材文件不存在：

- 仍显示 CSS 占位背景。
- 不白屏。
- 可以显示背景 ID 或调试提示。

### 验收标准

- 序章开头应用 `sha_qiu_night` 背景状态。
- 如果背景资源存在，能显示图片。
- 如果背景资源不存在，仍显示占位背景。
- 背景层不阻挡点击。
- 背景切换不会导致布局跳动。

## Step 8.4：实现立绘层

### 目标

根据 `show` 和 `hide` 标签显示角色立绘或占位。

### 实施内容

`PortraitLayer` 接收当前角色状态。

支持位置：

- `left`
- `center`
- `right`

支持表情：

- 通过 `character + expression` 查询 `data/assets.json`。
- 如果图片不存在，显示角色名和表情占位。

示例：

```text
show: huhai anxious left
show: zhao_gao serious right
show: zhao_gao smile right
hide: zhao_gao
```

### 验收标准

- 胡亥可显示在左侧。
- 赵高可显示在右侧。
- 赵高从 `serious` 更新为 `smile` 时，右侧状态变化。
- `hide: zhao_gao` 能移除赵高。
- 缺少立绘图片时显示占位，不白屏。
- 立绘层不阻挡文本框和选项点击。

## Step 8.5：实现音频控制

### 目标

根据 `music` 和 `sfx` 标签控制音频。

### 实施内容

最小实现：

- 读取 `music` 标签。
- 读取 `sfx` 标签。
- 在 UI 中显示当前 BGM 和待播放音效。
- 提供静音开关。

增强实现：

- BGM 循环播放。
- 切换 BGM 时停止旧音乐。
- SFX 单次播放。
- 浏览器阻止自动播放时，等待用户点击后再播放。

注意：

- 浏览器通常要求用户交互后才能播放音频。
- 如果素材文件不存在，不应报错导致页面崩溃。

### 验收标准

- 进入序章时能识别 `music: night_palace`。
- 进入序章时能识别 `sfx: door_open`。
- 页面提供静音开关。
- 没有音频素材时页面不崩溃。
- 如果实现实际播放，BGM 能循环，SFX 能单次播放。

## Step 8.6：接入 `GameView`

### 目标

在每次剧情推进后，应用当前 `StorySnapshot.tags` 到演出状态。

### 实施内容

在 `GameView` 中：

1. 获取 `snapshot.tags`。
2. 调用 `parseStoryTags`。
3. 更新演出状态。
4. 将背景状态传给 `BackgroundLayer`。
5. 将立绘状态传给 `PortraitLayer`。
6. 将音频状态传给音频控制或调试显示。

注意：

- 标签应作为“增量演出指令”应用，而不是每次完全重置。
- 重新开始时应重置演出状态。
- 读档或导入存档时，如果当前 Ink 状态无法重放历史标签，至少要保持页面可用，并在后续任务中补充 UI 状态存档。

### 验收标准

- 初始进入页面后背景、胡亥、赵高状态符合序章标签。
- 点击 A 后赵高表情状态更新。
- 点击 B 后隐藏/显示逻辑可执行。
- 点击重新开始后演出状态回到序章开头。
- 标签解析错误不会导致页面白屏。

## Step 8.7：补充占位素材策略

### 目标

在正式素材未完成时，保证表现层可见、可测试。

### 实施内容

两种方式任选其一：

方案 A：使用 CSS 占位。

- 背景用渐变和背景 ID 显示。
- 立绘用角色名、表情和位置占位。

方案 B：放入临时图片。

- `public/images/backgrounds/sha_qiu_night.webp`
- `public/images/backgrounds/side_hall_candle.webp`
- `public/images/portraits/huhai/anxious.webp`
- `public/images/portraits/zhao_gao/serious.webp`
- `public/images/portraits/zhao_gao/smile.webp`

### 验收标准

- 没有正式素材时仍能看出当前背景 ID。
- 没有正式素材时仍能看出角色、表情和位置。
- 缺失素材不会显示破损图标。

## Task 8 总体验收标准

- `src/engine/tags.ts` 能解析 `bg`、`show`、`hide`、`music`、`sfx`、`fade`、`shake`。

- 背景层能根据 `bg` 标签切换状态。
- 立绘层能根据 `show` 和 `hide` 标签切换状态。
- 音频标签能被识别，并至少在 UI 或调试状态中体现。
- 页面有静音开关。
- 缺少正式素材时仍有占位表现。

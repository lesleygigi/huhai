# Task 9：数据表落地 ✅

## 任务目标

将 `scripts/sheet.md` 中的系统数值、标记词典和结局触发条件整理为结构化 JSON 数据，供前端调试面板、路线判断和后续结局判定模块使用。

Task 9 完成后，项目应具备：

- 完整的主要数值定义表。
- 覆盖关键路线的标记词典。
- 可被程序读取的结局条件表。
- JSON 数据可被 TypeScript 模块读取。
- 数据能支撑 Task 6 调试面板和 Task 10 结局判定。

## 任务范围

需要涉及的文件：

```text
scripts/sheet.md
data/stats.json
data/flags.json
data/endings.json
src/engine/debug.ts
src/engine/endings.ts
```

不包含：

- 修改原始 `scripts/` Markdown 剧本。
- 实现完整结局判定 UI。
- 修改 Ink 剧情分支。

## Step 9.1：编写 `data/stats.json`

### 目标

从 `scripts/sheet.md` 的“隐藏数值追踪总表”抽取主要数值定义，并落地为结构化 JSON。

### 数据来源

优先来源：

```text
scripts/sheet.md
Sheet 1：隐藏数值追踪总表
1.1 数值类型定义
```

### 字段要求

每个数值对象包含：

```ts
type StatDefinition = {
  id: string;
  name: string;
  initial: number;
  min: number;
  max: number;
  description: string;
};
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `id` | 程序使用的稳定英文 key |
| `name` | 中文显示名 |
| `initial` | 初始值 |
| `min` | 最小值 |
| `max` | 最大值 |
| `description` | 数值用途说明 |

### 必须包含的数值

```text
cruelty           残暴值
prestige          威望值
fear              恐惧值
zhao_gao          赵高好感度
clan_support      宗室支持度
ziying            子婴好感度
zhang_han         章邯好感度
meng_yi           蒙毅好感度
strategy          权谋值
zhao_gao_evidence 赵高罪证
```

### 验收标准

- `data/stats.json` 是合法 JSON。
- 至少包含上述 10 个主要数值。
- 每个数值都有 `id`、`name`、`initial`、`min`、`max`、`description`。
- `id` 与 `story/main.ink` 中的变量名一致。
- 调试面板可以读取中文名称。
- `npm --cache ./.npm-cache run build` 构建成功。

## Step 9.2：编写 `data/flags.json`

### 目标

从 `scripts/sheet.md` 的“关键标记词典”和“标记互斥关系表”抽取关键标记定义。

### 数据来源

优先来源：

```text
scripts/sheet.md
Sheet 2：关键标记词典
2.1 标记列表
2.2 标记互斥关系表
```

### 字段要求

每个标记对象包含：

```ts
type FlagDefinition = {
  id: string;
  name: string;
  chapter: string;
  description: string;
  exclusiveGroup: string | null;
};
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `id` | 程序使用的稳定英文 key |
| `name` | 中文标记名，不带书名号 |
| `chapter` | 获取章节 |
| `description` | 标记效果或说明 |
| `exclusiveGroup` | 互斥组，无互斥则为 `null` |

### 必须覆盖的标记类别

序章路线：

- 矫诏同谋。
- 隐忍待发。
- 知情不报。
- 曾试图告发。

宗室路线：

- 宗室屠夫。
- 软禁宗室。
- 庇护宗室。

李斯路线：

- 诛杀李斯。
- 保李斯。

章邯路线：

- 重用章邯。
- 全力支持章邯。
- 猜忌章邯。

指鹿为马路线：

- 指鹿为鹿。
- 指鹿为马。
- 反将一军。

其他关键标记：

- 反杀赵高。
- 调虎离山。
- 亲征。
- 巨鹿大捷·亲征。
- 巨鹿解围。

### 建议互斥组

```text
prologue_route
clan_policy
li_si_policy
zhang_han_policy
deer_trial
```

### 验收标准

- `data/flags.json` 是合法 JSON。
- 至少包含序章、宗室、李斯、章邯、指鹿为马相关标记。
- 每个标记都有 `id`、`name`、`chapter`、`description`、`exclusiveGroup`。
- 同一互斥组中的标记可被 Task 6 调试面板检测冲突。
- 与 Ink 中已有标记名称保持一致。
- `npm --cache ./.npm-cache run build` 构建成功。

## Step 9.3：编写 `data/endings.json`

### 目标

从 `scripts/sheet.md` 的“结局数值阈值速查”和“结局触发条件速查表”抽取结局条件。

### 数据来源

优先来源：

```text
scripts/sheet.md
1.6 结局数值阈值速查
Sheet 3：结局触发条件速查表
```

### 字段要求

每个结局对象包含：

```ts
type EndingDefinition = {
  id: string;
  name: string;
  type: "HE" | "BE" | "TE";
  route: string;
  conditions: {
    min?: Record<string, number>;
    max?: Record<string, number>;
    flags?: string[];
    forbiddenFlags?: string[];
  };
};
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定英文 key |
| `name` | 结局显示名 |
| `type` | HE / BE / TE |
| `route` | 所属剧情线 |
| `conditions.min` | 数值下限条件 |
| `conditions.max` | 数值上限条件 |
| `conditions.flags` | 必需标记 |
| `conditions.forbiddenFlags` | 禁止标记 |

### 最低录入要求

至少录入：

HE：

- HE·明君逆袭。
- HE·重塑天下。
- HE·傀儡翻身。

BE：

- BE·宗室屠夫。
- BE·傀儡至死。
- BE·亡国罪人。

TE：

- TE·真实的二世。
- TE·迟来的觉醒。

### 验收标准

- `data/endings.json` 是合法 JSON。
- 至少录入 3 个 HE、3 个 BE、2 个 TE。
- 每个结局都有 `id`、`name`、`type`、`route`、`conditions`。
- 条件中的数值 key 与 `data/stats.json` 的 `id` 一致。
- 条件中的标记名与 `data/flags.json` 或 Ink 标记名一致。
- `src/engine/endings.ts` 后续可以读取并计算满足度。
- `npm --cache ./.npm-cache run build` 构建成功。

## Step 9.4：数据一致性检查

### 目标

避免 JSON 数据能解析但语义不一致。

### 检查内容

需要检查：

- `stats.json` 的 `id` 是否与 Ink 全局变量一致。
- `endings.json` 中的数值条件是否都存在于 `stats.json`。
- `endings.json` 中的标记条件是否能在 `flags.json` 找到，或确认为 Ink 中将来会使用的标记。
- `flags.json` 的互斥组是否能被调试面板读取。
- 所有 JSON 文件可解析。

### 可用验证命令

```bash
node -e "for (const f of ['data/stats.json','data/flags.json','data/endings.json']) { JSON.parse(require('fs').readFileSync(f,'utf8')); console.log(f + ' ok') }"
```

### 验收标准

- 三个 JSON 文件都能被解析。
- 没有重复 `id`。
- 结局条件没有引用不存在的数值 key。
- 构建成功。

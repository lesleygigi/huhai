# Task 4：Ink 编译与加载链路 ✅

## 任务目标

建立 Ink 剧情从 `.ink` 源文件到浏览器可运行 Story 实例的链路。

Task 4 完成后，项目应具备：

- 可以把 `story/main.ink` 编译为浏览器可加载的 JSON。
- 可以通过 `inkjs` 创建 Ink Story 实例。
- 可以读取当前剧情文本。
- 可以读取当前选项。
- 可以在代码层面选择选项并推进剧情。
- npm 脚本统一管理剧情编译、开发预览和前端构建。

## 任务范围

需要涉及的文件或目录：

```text
package.json
public/story/
story/main.ink
story/prologue.ink
src/engine/ink.ts
```

可能新增：

```text
public/story/main.json
```

不包含：

- 完整游戏 UI。
- 文本框、选项按钮等 React 组件渲染。
- 存档读档。
- 结局判定。
- 背景、立绘、音频演出。

这些内容分别属于后续 Task 5、Task 7、Task 8、Task 10。

## Step 4.1：确定 Ink 加载方式

### 目标

明确项目使用哪种方式让浏览器运行 Ink 剧情。

### 推荐方案

采用方案 A：

```text
story/main.ink
  -> 编译
public/story/main.json
  -> fetch 加载
inkjs Story
  -> 前端读取文本和选项
```

### 备选方案

如果 Ink 编译器暂时无法安装或运行，允许临时采用方案 B：

```text
手写最小 JSON 或手写最小 Story 数据
  -> 先验证前端播放器 UI
  -> Task 4 后续再补 Ink 编译链路
```

### 实施要求

- 优先使用真实 Ink 编译产物。
- 只在编译器受阻时使用临时数据。
- 如果使用临时方案，必须在文档或代码注释中记录阻塞原因。

### 验收标准

- 已明确最终采用方案 A。
- 若方案 A 受阻，已记录具体阻塞原因。
- 不把临时手写数据当成长期方案。

## Step 4.2：准备 Ink 编译器

### 目标

让项目可以把 `story/main.ink` 编译为 JSON。

### 实施内容

检查本机是否已有 `inklecate`：

```bash
command -v inklecate
```

如果本机已有 `inklecate`，直接使用：

```bash
inklecate -o public/story/main.json story/main.ink
```

如果本机没有 `inklecate`，需要选择一种安装方式：

- 使用系统已有包管理器安装。
- 下载官方 Ink 编译器。
- 使用项目本地工具链封装编译命令。

### 本地影响范围要求

- 不执行全局 npm 安装，例如 `npm install -g ...`。
- 不修改系统级 shell 配置。
- 不修改用户级 npm 配置。
- 如需下载或安装外部编译器，应先确认安装路径和影响范围。

### 验收标准

- `inklecate` 可执行，或已记录“当前不可用”的原因。
- 如果可执行，能生成 `public/story/main.json`。
- `public/story/main.json` 由 `story/main.ink` 编译生成。
- 编译失败时，错误信息已记录并可定位到具体 Ink 文件或语法。

## Step 4.4：增加 npm 脚本

### 目标

标准化剧情编译和开发命令。

### 实施内容

在 `package.json` 中增加或调整 scripts。

建议脚本：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "npm run story:build && tsc -b && vite build",
    "preview": "vite preview",
    "story:build": "inklecate -o public/story/main.json story/main.ink",
    "story:watch": "chokidar 'story/**/*.ink' -c 'npm run story:build'"
  }
}
```

如果暂时没有 `inklecate`，可以先不让 `build` 强依赖 `story:build`，但必须记录原因。

### npm cache 要求

执行 npm 命令时继续使用项目内缓存：

```bash
npm --cache ./.npm-cache run build
```

### 验收标准

- `package.json` 中存在 `story:build`。
- `package.json` 中存在 `story:watch`，或已记录暂不启用原因。
- `npm --cache ./.npm-cache run build` 可以构建前端，或失败原因明确。
- 如果 `build` 暂未串联 `story:build`，已记录原因。

## Step 4.5：实现 `src/engine/ink.ts` 的加载封装

### 目标

为后续 UI 提供稳定的 Ink Story 加载和推进接口。

### 实施内容

在 `src/engine/ink.ts` 中实现基础封装：

- 加载 `/story/main.json`。
- 创建 `inkjs` 的 Story 实例。
- 读取当前可继续文本。
- 读取当前选项。
- 选择某个选项。
- 推进剧情并返回当前快照。

建议接口：

```ts
export type StoryChoice = {
  index: number;
  text: string;
};

export type StorySnapshot = {
  lines: string[];
  choices: StoryChoice[];
  tags: string[];
};

export async function loadStory(): Promise<StoryRuntime>;
```

`StoryRuntime` 至少提供：

```ts
type StoryRuntime = {
  getSnapshot(): StorySnapshot;
  choose(index: number): StorySnapshot;
  restart(): StorySnapshot;
};
```

### 验收标准

- `src/engine/ink.ts` 不再只是空占位。
- 可以从 `/story/main.json` 创建 Story 实例。
- 可以读取当前文本行。
- 可以读取当前选项。
- 可以选择选项并推进剧情。
- 读取标签时保留 Ink 当前 tags，供 Task 8 使用。

## Step 4.6：最小运行验证

### 目标

在不依赖完整 UI 的情况下，验证 Ink 编译产物和加载封装可用。

### 验证方式

可选方式 A：临时在浏览器控制台或开发代码中调用 `loadStory()`。

可选方式 B：编写轻量测试脚本或临时调试入口，打印：

```text
当前文本 lines
当前选项 choices
当前 tags
选择第一个选项后的新文本
```

### 验收标准

- 能创建 Ink Story 实例。
- 初始快照包含序章文本。
- 初始快照包含 A/B/C 三个选择，或能推进到包含 A/B/C 的节点。
- 点击或调用选择后，剧情进入对应临时结算段落。
- 选择 A 后能体现【矫诏同谋】对应状态变化。
- 选择 C 后能体现【隐忍待发】对应状态变化。

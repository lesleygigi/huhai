# Task 10：结局判定模块 ✅

## 任务目标

实现基于当前数值和标记的结局判定模块，并接入调试面板，让作者在测试剧情分支时能看到“可能结局”“缺失条件”和“锁死原因”。

Task 10 完成后，应能：

- 读取 `data/endings.json`。
- 根据当前变量判断 `min` 条件。
- 根据当前变量判断 `max` 条件。
- 判断必需标记。
- 判断禁止标记。
- 输出已满足条件。
- 输出未满足条件。
- 输出锁死原因。
- 在调试面板中显示最接近的结局。

## Step 10.1：定义结局判定类型

### 目标

为结局判定结果建立稳定数据结构，便于前端显示。

### 实施内容

在 `src/engine/endings.ts` 中定义：

```ts
export type EndingMatch = {
  id: string;
  name: string;
  type: "HE" | "BE" | "TE";
  route: string;
  matched: boolean;
  score: number;
  satisfied: string[];
  missing: string[];
  locked: string[];
};
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `matched` | 是否完全满足 |
| `score` | 满足度，用于排序 |
| `satisfied` | 已满足条件说明 |
| `missing` | 未满足条件说明 |
| `locked` | 锁死原因，例如禁止标记或关键条件冲突 |

### 验收标准

- `EndingMatch` 类型存在。
- 判定结果能表达已满足、未满足和锁死原因。
- 类型包含 `score`，可用于排序最接近结局。

## Step 10.2：实现数值条件判定

### 目标

支持 `conditions.min` 和 `conditions.max`。

### 实施内容

读取当前变量：

```ts
snapshot.variables
```

判断规则：

- `min.foo = 7` 表示当前 `foo >= 7`。
- `max.foo = 3` 表示当前 `foo <= 3`。

输出示例：

```text
已满足：残暴值 <= 3
未满足：威望值还差 2
```

需要使用 `data/stats.json` 的中文名。

### 验收标准

- 能判断所有 `min` 条件。
- 能判断所有 `max` 条件。
- 缺失变量按 0 处理，或明确使用初始值。
- 输出中文变量名。
- 能说明差值，例如“还差 2”或“超出 1”。

## Step 10.3：实现标记条件判定

### 目标

支持必需标记和禁止标记。

### 实施内容

读取当前标记：

```ts
getFlagNames(snapshot.variables.flags)
```

判断规则：

- `conditions.flags` 中的标记必须全部存在。
- `conditions.forbiddenFlags` 中的标记如果存在，则该结局锁死。

输出示例：

```text
已满足：拥有【庇护宗室】
未满足：缺少【巨鹿大捷】
锁死：存在【宗室屠夫】
```

### 验收标准

- 能判断必需标记。
- 能判断禁止标记。
- 标记显示使用【】格式。
- 缺少标记进入 `missing`。
- 禁止标记命中进入 `locked`。

## Step 10.4：计算满足度和排序

### 目标

让调试面板能显示最接近的结局，而不是无序列出全部结局。

### 实施内容

建议评分规则：

- 每满足一个条件，`score + 1`。
- 每缺失一个条件，不加分。
- 每个锁死原因，结局排序靠后。
- 完全满足时 `matched = true`。

排序建议：

1. `matched = true` 的结局最前。
2. 未锁死的结局优先。
3. `score` 高的结局优先。
4. HE、TE、BE 的显示顺序可保持数据表顺序或按类型分组。

### 验收标准

- `getEndingMatches()` 返回按接近程度排序的数组。
- 完全满足的结局 `matched = true`。
- 锁死结局不会排在未锁死结局前面。
- 至少能显示前三个最接近结局。

## Step 10.6：接入调试面板

### 目标

让作者边玩边看结局走向。

### 实施内容

显示内容：

```text

HE·明君逆袭
已满足：残暴值 <= 3，恐惧值 <= 2
未满足：威望值还差 7，缺少【巨鹿大捷】

```

建议只显示前 3-5 个结局，避免面板过长。

### 验收标准

- 调试面板显示“可能结局”。
- 能显示结局名称、类型和路线。
- 能显示已满足条件。
- 能显示未满足条件。
- 能显示锁死原因。
- 没有锁死时显示“无”或隐藏锁死区域。

## Step 10.7：验证锁死逻辑

### 目标

确认禁止标记或关键负面标记能影响结局显示。

### 实施内容

至少为部分 HE 增加禁止标记条件，例如：

```json
"forbiddenFlags": ["宗室屠夫"]
```

验证场景：

- 当前有【宗室屠夫】时，部分 HE 显示锁死。
- 当前没有【宗室屠夫】时，HE 不因该条件锁死。

### 验收标准

- `data/endings.json` 中至少一个 HE 使用 `forbiddenFlags`。
- 当获得【宗室屠夫】时，调试面板显示部分 HE 锁死。
- 锁死原因明确显示为存在【宗室屠夫】。

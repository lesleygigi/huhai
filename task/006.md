# Task 6：调试面板 ✅

## 任务目标

实现创作用调试面板，让作者在游玩序章原型时能实时查看剧情状态。

Task 6 完成后，调试面板应能显示：

- 当前路线。
- 当前数值。
- 当前标记。
- 互斥标记冲突提醒。
- 选择历史。
- 当前 Ink 标签。

该面板面向开发和创作调试，不是最终玩家 UI。

## 任务范围

需要涉及的文件：

```text
src/components/DebugPanel.tsx
src/components/GameView.tsx
src/engine/ink.ts
src/styles/game.css
data/stats.json
data/flags.json
```

可选新增：

```text
src/engine/debug.ts
```

依赖前置任务：

- Task 4：`src/engine/ink.ts` 可以读取变量、标签和选项。
- Task 5：`GameView` 可以显示游戏界面并推进剧情。

不包含：

- 存档读档。
- 结局判定。
- 完整路线树可视化。
- 正式玩家 UI。

## Step 6.1：显示变量

### 目标

让作者在点击选择后能立即看到隐藏数值变化。

### 实施内容

调试面板应读取 `StorySnapshot.variables` 中的变量，并结合 `data/stats.json` 显示中文名称。

需要显示的变量：

| 变量 | 中文名 |
| --- | --- |
| `cruelty` | 残暴值 |
| `prestige` | 威望值 |
| `fear` | 恐惧值 |
| `zhao_gao` | 赵高好感度 |
| `clan_support` | 宗室支持度 |
| `ziying` | 子婴好感度 |
| `zhang_han` | 章邯好感度 |
| `meng_yi` | 蒙毅好感度 |
| `strategy` | 权谋值 |
| `zhao_gao_evidence` | 赵高罪证 |

建议显示内容：

```text
恐惧值：1
赵高好感度：2
权谋值：0
```

### 验收标准

- 调试面板能显示全部主要变量。
- 变量显示中文名，而不是只显示英文 key。
- 初始状态下变量值为初始值。
- 点击“同意矫诏”后：
  - 恐惧值变为 1。
  - 赵高好感度变为 2。
- 点击“表面答应，暗中布局”后：
  - 恐惧值变为 1。
  - 权谋值变为 1。
- 点击“重新开始”后变量恢复初始状态。

## Step 6.2：显示标记

### 目标

让作者能确认当前路线和关键剧情标记是否正确获得。

### 实施内容

从 `StorySnapshot.variables.flags` 中读取当前 Ink LIST 值，并转换为可读标记列表。

建议显示格式：

```text
当前标记：
【矫诏同谋】
```

如果没有获得任何标记，显示：

```text
当前标记：无
```

### 标记名称来源

优先读取 Ink 变量 `flags` 当前值。

如果需要中文说明，可结合 `data/flags.json`：

```json
{
  "name": "矫诏同谋",
  "description": "赵高视胡亥为同谋，主线开启。"
}
```

### 验收标准

- 初始状态显示“当前标记：无”或等价空状态。
- 选择“同意矫诏”后显示【矫诏同谋】。
- 选择“拒绝并告发”后显示【曾试图告发】。
- 选择“表面答应，暗中布局”后显示【隐忍待发】。
- 点击“重新开始”后标记清空。

## Step 6.3：互斥标记冲突提醒

### 目标

让作者能快速发现脚本中不应同时出现的路线标记。

### 实施内容

读取 `data/flags.json` 中的 `exclusiveGroup`。

同一 `exclusiveGroup` 中，如果当前获得超过一个标记，应在调试面板中显示冲突提醒。

示例：

```text
标记冲突：
prologue_route：矫诏同谋、隐忍待发
```

当前序章路线互斥组：

```text
prologue_route
```

其中互斥标记包括：

- 矫诏同谋。
- 隐忍待发。
- 知情不报。

备注：

- 【曾试图告发】不是 `prologue_route` 的互斥成员，可与后续路线状态并存。
- 如果 `flags.json` 中定义不同，应以 `flags.json` 为准。

### 验收标准

- 正常选择 A/B/C 时不出现冲突提醒。
- 如果手动制造同一互斥组的多个标记，调试面板能显示冲突。
- 没有冲突时显示“无冲突”或不显示冲突区域。

## Step 6.4：显示选择历史

### 目标

方便作者复盘当前测试路径。

### 实施内容

`GameView` 在每次选择时记录选择历史。

每条历史至少包含：

- 顺序编号。
- 玩家选择文本。
- 选择后的路线或关键标记快照。

建议类型：

```ts
type ChoiceHistoryItem = {
  id: number;
  text: string;
  routeName: string;
  flags: string[];
};
```

最低可接受实现：

```text
1. 同意矫诏
```

增强实现：

```text
1. 同意矫诏 -> 主线 -> 【矫诏同谋】
```

### 验收标准

- 初始状态显示“尚未选择”。
- 每次点击选择后，历史记录追加一条。
- 点击“重新开始”后历史记录清空。
- 历史记录不会因为状态刷新重复追加。

## Step 6.5：显示当前路线

### 目标

快速判断当前处于主线、隐忍线、告发线或沉默线。

### 路线规则

建议规则：

| 条件 | 路线名称 |
| --- | --- |
| 有【矫诏同谋】 | 主线 |
| 有【隐忍待发】 | 隐忍线 |
| 有【知情不报】 | 沉默线 |
| 有【曾试图告发】 | 告发失败线或告发线 |
| 无路线标记 | 序章 |

如果多个条件同时满足：

- 优先显示互斥冲突提醒。
- 路线名称可以显示“路线冲突”。

### 验收标准

- 初始状态显示“序章”。
- 选择“同意矫诏”后显示“主线”。
- 选择“表面答应，暗中布局”后显示“隐忍线”。
- 选择“拒绝并告发”后显示“告发线”或“告发失败线”。
- 重新开始后回到“序章”。

## Step 6.6：显示当前 Ink 标签

### 目标

验证剧情演出标签是否从 Ink 正确传到前端。

### 实施内容

显示 `StorySnapshot.tags`。

建议显示：

```text
当前标签：
bg: sha_qiu_night
music: night_palace
show: huhai anxious left
show: zhao_gao serious right
```

### 验收标准

- 初始序章能显示 `bg: sha_qiu_night`。
- 初始序章能显示 `show: zhao_gao serious right`。
- 选择 A 后能显示 `show: zhao_gao smile right`。
- 标签为空时显示空状态。

## Step 6.7：调试面板布局

### 目标

让调试信息可读，并且不阻挡核心游玩。

### 实施内容

调试面板样式要求：

- 固定在屏幕右上角或可折叠。
- 最大高度受限，内容可滚动。
- 不遮挡文本框和选项区的主要交互。
- 移动端下不造成横向滚动。
- 数值、标记、标签、历史有清晰分区。

### 验收标准

- 桌面端可同时看到剧情和调试信息。
- 移动端不出现横向滚动。
- 调试面板内容过多时可滚动。
- 调试面板不会挡住选项按钮。

## Task 6 总体验收标准

Task 6 完成时应满足：

- 调试面板显示当前路线。
- 调试面板显示全部主要变量。
- 调试面板使用中文变量名。
- 调试面板显示当前标记。
- 调试面板能提示互斥标记冲突。
- 调试面板显示选择历史。
- 调试面板显示当前 Ink 标签。
- 点击不同选择后变量、标记、路线和历史实时更新。
- 点击“重新开始”后变量、标记、路线和历史恢复初始状态。
- `npm --cache ./.npm-cache run build` 构建成功。
- 未修改 `scripts/` 原始 Markdown 剧本。

# Task 7：存档与读档 ✅

## 任务目标

实现《胡亥模拟器》的基础存档、读档和 JSON 导入导出能力，方便玩家继续游玩，也方便作者复现测试路径和 bug。

Task 7 完成后，应能：

- 将当前 Ink 剧情状态保存到 `localStorage`。
- 保存选择历史和必要 UI 状态。
- 从本地存档恢复剧情位置、变量、标记和选择历史。
- 导出当前存档 JSON。
- 粘贴 JSON 后导入并恢复进度。

## 任务范围

需要涉及的文件：

```text
src/engine/save.ts
src/engine/ink.ts
src/components/GameView.tsx
src/components/DebugPanel.tsx
src/styles/game.css
```

可选新增：

```text
src/components/SavePanel.tsx
```

依赖前置任务：

- Task 4：`StoryRuntime` 可以返回 Ink 状态 JSON。
- Task 5：`GameView` 可以推进剧情和重新开始。
- Task 6：选择历史已经结构化。

不包含：

- 存档版本迁移系统。
- 正式玩家菜单 UI。

## Step 7.1：定义存档数据结构

### 目标

明确一次存档需要保存哪些数据，避免只保存 Ink 状态导致 UI 状态丢失。

### 实施内容

建议在 `src/engine/save.ts` 中定义：

```ts
export type SaveData = {
  version: 1;
  savedAt: string;
  inkStateJson: string;
  history: ChoiceHistoryItem[];
};
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `version` | 存档格式版本，初始为 `1` |
| `savedAt` | ISO 时间字符串 |
| `inkStateJson` | `story.state.ToJson()` 的结果 |
| `history` | 当前选择历史 |

可选字段：

```ts
ui?: {
  routeName?: string;
};
```

### 验收标准

- 存档类型在代码中有明确声明。
- 存档中包含 Ink 状态。
- 存档中包含选择历史。
- 存档中包含版本号。
- 存档中包含保存时间。

## Step 7.2：扩展 Ink 运行时恢复能力

### 目标

让 `StoryRuntime` 不只能导出 Ink 状态，还能恢复 Ink 状态。

### 实施内容

在 `src/engine/ink.ts` 中扩展运行时接口：

```ts
export type StoryRuntime = {
  getSnapshot: () => StorySnapshot;
  choose: (index: number) => StorySnapshot;
  restart: () => StorySnapshot;
  toJson: () => string;
  loadJson: (stateJson: string) => StorySnapshot;
};
```

实现逻辑：

```ts
story.state.LoadJson(stateJson);
snapshot = continueToChoice(story);
return snapshot;
```

注意：

- `loadJson` 应恢复变量、标记、当前剧情位置。
- 恢复后应返回新的 `StorySnapshot`。
- 如果导入无效 JSON，应抛出可读错误。

### 验收标准

- `StoryRuntime` 暴露 `loadJson`。
- 调用 `loadJson` 后可以恢复到保存时的剧情位置。
- 调用 `loadJson` 后变量和标记正确恢复。
- 无效 JSON 不导致页面白屏，应显示错误或提示。

## Step 7.3：实现本地保存

### 目标

点击保存后，把当前进度写入浏览器 `localStorage`。

### 实施内容

在 `src/engine/save.ts` 中实现：

```ts
export function writeSave(data: SaveData): void;
export function readSave(): SaveData | null;
export function clearSave(): void;
```

本地存档 key：

```ts
const saveKey = "huhai-save";
```

在 `GameView` 中增加“保存”按钮。

保存时写入：

- `runtime.toJson()`
- 当前 `history`
- 当前时间
- 存档版本

### 验收标准

- 页面上存在“保存”按钮。
- 点击“保存”后 `localStorage` 中出现 `huhai-save`。
- 保存后有成功提示或状态反馈。
- 保存内容包含 Ink 状态和选择历史。
- 保存不会重置当前剧情。

## Step 7.4：实现本地读档

### 目标

从 `localStorage` 恢复上一次保存的进度。

### 实施内容

在 `GameView` 中增加“读档”按钮。

读档流程：

1. 调用 `readSave()`。
2. 如果没有存档，显示提示。
3. 如果有存档，调用 `runtime.loadJson(save.inkStateJson)`。
4. 恢复 `history`。
5. 更新当前 `StorySnapshot`。

### 验收标准

- 页面上存在“读档”按钮。
- 没有存档时点击读档，不会报错或白屏。
- 点击保存后刷新页面，再点击读档，可以恢复保存时的状态。
- 读档后变量、标记、路线正确。
- 读档后选择历史正确恢复。
- 如果保存点仍有选项，读档后可以继续选择。

## Step 7.5：实现清除存档

### 目标

方便测试时清空本地存档。

### 实施内容

在 `GameView` 中增加“清除存档”按钮。

按钮行为：

```ts
clearSave();
```

清除后显示反馈。

### 验收标准

- 页面上存在“清除存档”按钮。
- 点击后 `localStorage` 中的 `huhai-save` 被删除。
- 删除后点击读档，显示无存档提示。
- 清除存档不影响当前正在游玩的运行时状态。

## Step 7.6：实现导出 JSON

### 目标

方便作者把当前状态保存为可复制文本，用于 bug 复现。

### 实施内容

在界面上提供“导出 JSON”功能。

最低可接受实现：

- 点击按钮后生成当前 `SaveData`。
- 显示在一个只读 `textarea` 中。
- 作者可以手动复制。

增强实现：

- 使用 Clipboard API 复制到剪贴板。
- 复制失败时回退到 `textarea`。

### 验收标准

- 点击“导出 JSON”后可以看到一段完整 JSON。
- JSON 可以被 `JSON.parse` 解析。
- JSON 中包含 `inkStateJson`。
- JSON 中包含 `history`。
- 导出的 JSON 不包含函数或不可序列化对象。

## Step 7.7：实现导入 JSON

### 目标

允许通过粘贴 JSON 恢复某个测试路径。

### 实施内容

提供输入区域：

```text
粘贴存档 JSON
```

导入流程：

1. 用户粘贴 JSON。
2. 点击“导入 JSON”。
3. `JSON.parse` 解析。
4. 校验是否包含 `version`、`inkStateJson`、`history`。
5. 调用 `runtime.loadJson(data.inkStateJson)`。
6. 恢复 `history`。
7. 更新当前 `StorySnapshot`。

错误处理：

- JSON 格式错误时显示提示。
- 缺少必要字段时显示提示。
- Ink 状态无法恢复时显示提示。

### 验收标准

- 可以粘贴导出的 JSON 并导入。
- 导入后剧情位置恢复。
- 导入后变量和标记恢复。
- 导入后选择历史恢复。
- 无效 JSON 不会导致页面白屏。

## Step 7.8：存档 UI 布局

### 目标

让存档功能可用且不干扰最小游戏播放器。

### 实施内容


- `textarea` 不会撑破布局。
- 移动端不出现横向滚动。
- 状态提示清晰。

### 验收标准

- 存档按钮可见。
- 导入导出区域可用。
- 长 JSON 文本不会破坏布局。
- 移动端布局稳定。

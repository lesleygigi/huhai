# Task 14：菜单系统原型落地

## 任务目标

把右上角菜单从“工具集合面板”整理成可扩展的游戏菜单系统。

Task 14 完成后，菜单应至少支持：

- 保存档案。
- 读取档案。
- 个人属性。
- 人物好感。
- 已获标记。
- 历史回看。
- 设置。
- 重新开始。

## 任务范围

主要涉及文件：

```text
src/components/GameView.tsx
src/components/SavePanel.tsx
src/components/HistoryPanel.tsx
src/components/SettingsPanel.tsx
src/components/DebugPanel.tsx
src/styles/game.css
src/engine/debug.ts
src/engine/save.ts
data/stats.json
```

可选新增：

```text
src/components/GameMenu.tsx
src/components/StatsPanel.tsx
src/components/RelationsPanel.tsx
src/components/FlagsPanel.tsx
```

不包含：

- 多存档槽位。
- 云存档。
- 正式 UI 动效。
- 完整音频设置系统。
- 新增剧情变量，除非确认为当前数据缺失。

## Step 14.1：整理菜单入口和菜单布局

### 目标

右上角汉堡按钮展开后，显示清晰的菜单入口，而不是把所有工具内容直接堆在同一个长面板里。

### 实施内容

菜单展开后建议显示：

```text
继续游戏
保存档案
读取档案
个人属性
人物好感
已获标记
历史回看
设置
重新开始
```

最低实现：

- 保留右上角三横杠菜单按钮。
- 点击后打开菜单面板。
- 菜单面板显示上述入口。
- 点击“继续游戏”关闭菜单。
- 点击不同入口可以切换当前菜单内容。

### 验收标准

- 菜单按钮仍在右上角。
- 菜单展开后不遮挡整个主界面失控。
- 菜单入口文本清晰。
- 点击“继续游戏”可以关闭菜单。
- `npm --cache ./.npm-cache run build` 构建成功。

## Step 14.2：保存档案面板

### 目标

提供明确的保存入口。

### 实施内容

保存档案面板至少包含：

- 保存当前进度。
- 导出存档 JSON。
- 保存状态提示。
- 当前存档保存时间，如果已有。

可复用现有 `SavePanel` 的保存和导出能力，但 UI 上需要明确区分“保存”和“读取”。

### 验收标准

- 点击“保存档案”进入保存面板。
- 点击保存后写入本地存档。
- 保存后显示保存时间。
- 点击导出后生成 JSON。
- 保存面板不显示导入 JSON 输入框。

## Step 14.3：读取档案面板

### 目标

提供明确的读档和导入入口。

### 实施内容

读取档案面板至少包含：

- 读取本地存档。
- 导入 JSON 存档。
- 粘贴 JSON 文本框。
- 清除本地存档。
- 读取/导入/清除状态提示。

### 验收标准

- 点击“读取档案”进入读取面板。
- 读取本地存档后恢复剧情状态。
- 导入 JSON 后恢复剧情状态。
- 清除存档后再次读取会提示没有本地存档。
- 读取面板不显示导出 JSON 文本框。

## Step 14.4：个人属性面板

### 目标

让玩家可以查看胡亥自身状态。

### 实施内容

个人属性面板展示当前 `snapshot.variables` 中的主角属性。

建议字段：

```text
恐惧 fear
权谋 strategy
威望 prestige
残暴 cruelty
宗室支持 clan_support
赵高罪证 zhao_gao_evidence
```

展示方式可以先用数字列表：

```text
恐惧        1
权谋        0
威望        0
残暴        0
宗室支持    0
赵高罪证    0
```

### 验收标准

- 点击“个人属性”进入属性面板。
- 属性值来自当前 Ink 变量。
- 选择不同剧情选项后，属性值能反映变化。
- 没有变量时显示默认值或 `0`，不白屏。

## Step 14.5：人物好感面板

### 目标

让玩家可以查看与主要人物的关系状态。

### 实施内容

人物好感面板展示当前关系变量。

当前可用字段：

```text
赵高 zhao_gao
蒙毅 meng_yi
子婴 ziying
章邯 zhang_han
```

可选后续字段：

```text
李斯 li_si
```

如果本任务不新增 `li_si`，需要在文档或界面中暂不显示李斯，避免显示不存在变量。

### 验收标准

- 点击“人物好感”进入好感面板。
- 好感值来自当前 Ink 变量。
- 选择序章 A 后，赵高好感变化可见。
- 选择序章 B 后，蒙毅好感变化可见。
- 不存在的变量不会导致白屏。

## Step 14.6：已获标记面板

### 目标

让玩家可以查看关键路线标记。

### 实施内容

读取 `snapshot.variables.flags`，显示当前已获得标记。

建议展示：

```text
已获标记

【矫诏同谋】
【隐忍待发】
【曾试图告发】
【扶苏同盟】
【蒙毅的默契】
```

如果没有标记，显示：

```text
尚未获得标记
```

### 验收标准

- 点击“已获标记”进入标记面板。
- 序章 A 后显示【矫诏同谋】。
- 序章 B 后显示【曾试图告发】。
- 序章 C 后显示【隐忍待发】。
- 没有标记时显示空状态。

## Step 14.7：历史回看和设置入口整合

### 目标

保留现有历史与设置能力，但入口从主菜单进入。

### 实施内容

- “历史回看”打开现有 `HistoryPanel` 或菜单内历史页。
- “设置”打开现有 `SettingsPanel` 或菜单内设置页。
- 字号、静音等现有设置继续生效。

### 验收标准

- 点击“历史回看”可以看到已读文本和选择。
- 点击“设置”可以修改字号、文本速度、音量和静音。
- 修改设置后刷新仍保留。

## Step 14.8：移除调试信息对玩家菜单的干扰

### 目标

玩家菜单和开发调试信息分离。

### 实施内容

当前 `DebugPanel` 可以暂时保留，但不应作为玩家菜单的默认内容。

建议：

- 菜单默认显示玩家功能入口。
- 调试信息只在开发模式或单独入口中显示。
- 如果暂不做开发模式判断，可以将调试入口隐藏或放到菜单底部。

### 验收标准

- 打开菜单时不会直接看到大量调试信息。
- 玩家入口优先级高于调试入口。
- 保留调试能力不影响构建。

## Task 14 总体验收标准

Task 14 完成时应满足：

- 右上角三横杠菜单可以打开菜单。
- 菜单至少包含：
  - 继续游戏
  - 保存档案
  - 读取档案
  - 个人属性
  - 人物好感
  - 已获标记
  - 历史回看
  - 设置
  - 重新开始
- 保存和读取职责分离。
- 个人属性能显示当前主角数值。
- 人物好感能显示当前关系数值。
- 已获标记能显示当前 flags。
- 历史和设置功能仍可用。
- 菜单 UI 不遮挡或破坏主游戏布局。
- `npm --cache ./.npm-cache run build` 构建成功。

## 建议验证路径

```bash
npm --cache ./.npm-cache run build
npm --cache ./.npm-cache run dev -- --host 127.0.0.1
```

手动验收：

1. 打开游戏。
2. 点击右上角三横杠菜单。
3. 点击“继续游戏”，确认菜单关闭。
4. 再次打开菜单，进入“个人属性”，确认数值显示。
5. 进入“人物好感”，确认关系显示。
6. 进入“已获标记”，确认初始为空。
7. 选择序章 A/B/C 任一路线。
8. 再打开菜单，确认属性、好感、标记变化。
9. 进入“保存档案”，保存当前进度。
10. 刷新页面。
11. 进入“读取档案”，读取本地存档。
12. 确认剧情状态恢复。
